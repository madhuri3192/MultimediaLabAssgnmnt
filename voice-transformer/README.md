# Retone — AI Speech-to-Speech Voice Transformer (MVP)

Record or upload up to 30 seconds of speech and hear the **same performance** — words, timing, pauses, emphasis, emotion — rendered in a different synthetic AI voice. Optionally download the result as MP3.

> **Status:** non-commercial technical prototype built on the ElevenLabs **free plan**. It is not a production SaaS. Commercial use requires an appropriate paid ElevenLabs plan and a review of their terms.
>
> **Live demo:** [voice-transformer.vercel.app](https://voice-transformer.vercel.app) — shares one free monthly quota, so please keep clips short.

## What this is (and isn't)

This is **speech-to-speech voice conversion**. The source audio is sent as audio to ElevenLabs Voice Changer and comes back as audio. Nothing is transcribed, rewritten, translated or regenerated by a language model; the spoken performance is preserved and only the perceived voice changes.

It is **not** text-to-speech, not speech-to-text followed by TTS, not a pitch shifter, not a chatbot, and not live/continuous voice conversion.

## Architecture

```
Browser (record via MediaRecorder, or upload a file)
  → client-side validation (format, size, duration ≤ 30 s)
  → POST multipart/form-data  /api/convert  { audio, voiceSlug }
      → Next.js route handler (Node runtime)
      → server-side validation: config → allowlisted voice slug → size → format
        → real container/duration probe (music-metadata + WebM block scanner)
      → ElevenLabs POST /v1/speech-to-speech/{voice_id}  (eleven_multilingual_sts_v2, mp3_44100_128)
      ← MP3 bytes, Cache-Control: no-store
  ← in-memory Blob → <audio> player (autoplay attempted) → optional download
```

The ElevenLabs API key lives only in a server environment variable and never reaches the browser. The browser sends an internal voice *slug* (`warm-narrator`, `deep-studio`, `bright-conversational`); the server maps it to a trusted voice ID. See [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) for the full design and [docs/ROADMAP.md](docs/ROADMAP.md) for what comes next.

## Current functionality

- Record from the microphone (≤ 30 s, timer, level meter, manual stop, automatic stop at the limit, preview, re-record)
- Upload an audio file (click or drag-and-drop; MP3, WAV, M4A, OGG/OGA, FLAC, WebM; ≤ 30 s; ≤ 15 MB by default)
- Choose one of up to three developer-configured synthetic target voices
- Transform via ElevenLabs Speech-to-Speech with a real-progress processing state (no fake percentages)
- Play the result in the browser (autoplay attempted, visible controls always present), compare with the original, download as MP3
- Multilingual model, so English, Hindi and Hinglish speech work
- Human-readable errors for every failure mode, including free-quota exhaustion
- Responsive, keyboard-accessible, screen-reader-friendly, reduced-motion aware, light/dark

## Current limitations

- No real-time / continuous transformation (batch only, ≤ 30 s)
- No user voice cloning (needs a paid ElevenLabs plan and a consent flow — see roadmap)
- No accounts, history, database or persistent storage of any kind
- Bound by the ElevenLabs free-plan quota (roughly 10 minutes of Voice Changer per month)
- Audio is processed by ElevenLabs, an external provider (see Privacy)
- Free-tier output is for non-commercial prototype use
- Safari's MediaRecorder produces MP4/AAC; it is supported in code but was not verified on Apple hardware during development

## ElevenLabs setup (free plan)

1. Create a free account at [elevenlabs.io](https://elevenlabs.io).
2. Go to **Profile → API keys** and create a **dedicated key for this app**.
   - Restrict its permissions to what the app needs (**Speech to Speech** / Voice Changer, plus reading voices) if the scope controls are available on your plan.
   - Set a **credit limit** on the key so a bug or abuse can never spend more than you intend.
   - Never reuse an unrestricted personal key. If a key is ever exposed, revoke and rotate it immediately.
3. Pick voices that the **free plan can use through the API** — this is the step that trips people up:

   | Voice source | Works on free via API? | How to tell |
   | --- | --- | --- |
   | **Voice Design** voices you generate and save (category `generated`) | ✅ yes | You created it under *Voices → Voice Design* |
   | ElevenLabs' **current built-in default voices** (category `premade`, e.g. George, Sarah, Laura, Charlie) | ✅ yes — verified | Present in *My Voices* on a brand-new account; not "added" by you |
   | Anything added from the **Voice Library** — including legacy defaults such as Rachel, Adam, Bella | ❌ no — `402 paid_plan_required` "Free users cannot use library voices via the API" | You clicked *Add to My Voices* on someone else's voice |
   | Instant / Professional clones | ❌ not available on free | — |

   Recommended: open **Voices → Voice Design**, generate 1–3 synthetic voices from neutral briefs (*warm, calm narrator* · *lower, cinematic studio voice* · *bright, friendly conversational voice*) and save them. Do **not** describe or name real people. Free accounts have a small number of custom voice slots.

   Quick start without designing anything: use two built-in default voices that were verified on the free plan while building this app — **George** `JBFqnCBsd6RMkjVDRZzb` (deeper) and **Sarah** `EXAVITQu4vr4xnSDxMaL` (brighter). They are ElevenLabs stock synthetic voices; the app shows them under its own neutral names.
4. Copy each voice's **Voice ID** (Voices → the voice → ⋯ → *Copy voice ID*).
5. Run `pnpm check:elevenlabs --probe` after configuring (see Troubleshooting) — it tells you in one line whether each configured voice will work.
6. Create `.env.local` from the template and fill it in:
   ```sh
   cp .env.example .env.local
   ```
   ```env
   ELEVENLABS_API_KEY=sk_...
   ELEVENLABS_VOICE_WARM_ID=...
   ELEVENLABS_VOICE_DEEP_ID=...      # optional
   ELEVENLABS_VOICE_BRIGHT_ID=...    # optional
   ```
   Only the voices with an ID configured are shown. If nothing is configured the app renders a setup checklist instead of crashing.
7. Run the app (below). The first conversion confirms the key and voice IDs work.

The app never fetches the public Voice Library through the API; it uses only the voices you configure.

## Development

Requirements: Node.js 20.11+ (24 recommended) and pnpm 10.

```sh
cd voice-transformer
pnpm install
cp .env.example .env.local   # then edit
pnpm dev                     # http://localhost:3000
```

Quality gates:

```sh
pnpm lint        # ESLint (next/core-web-vitals + typescript + react-hooks)
pnpm typecheck   # tsc --noEmit
pnpm test        # Vitest (unit + API route + UI state transitions; no network, no credits)
pnpm build       # next build
pnpm verify      # all of the above
pnpm check:elevenlabs [--probe]   # diagnose the ElevenLabs configuration (see Troubleshooting)
```

Tests never contact ElevenLabs: the provider is mocked, and container parsing is tested against tiny synthetic sine-tone fixtures in `tests/fixtures/`.

In development the browser console logs one timing line per conversion (`[voice-transformer] conversion timing`) with round-trip, server and provider durations, and the server prints structured JSON log lines (`convert.start`, `convert.success`, `convert.rejected`, `convert.provider_failed`). Logs contain durations, sizes, status codes, the internal voice slug and, on provider failures, the provider's short error explanation (`providerMessage`) — never audio or keys.

## Troubleshooting

```sh
pnpm check:elevenlabs          # key present? plan, credits left, model, and each configured voice
pnpm check:elevenlabs --probe  # + one real 2-second conversion per voice (~35 credits each)
```

The read-only checks need the key permissions `user_read`, `voices_read` and `models_read`; a key restricted to Speech-to-Speech only can still run `--probe`, which is the definitive test. The script never prints the key.

| Symptom | Meaning | Fix |
| --- | --- | --- |
| UI: "Target voice not available on this plan"; log: `providerDetail: "paid_plan_required"` | The configured voice is a Voice Library voice; free accounts can't use those via the API | Use a Voice Design voice or a current built-in default voice (table above) |
| UI: "Demo usage limit reached"; log: `insufficient_credits` / `quota_exceeded` | Monthly free credits are used up | Wait for the reset (dashboard → Usage) or upgrade |
| UI: "Voice service configuration problem"; log: `providerStatus: 401` | Key invalid, revoked or missing the Speech-to-Speech permission | Create/repair the key |
| UI: "Target voice unavailable"; log: `voice_not_found` | Voice ID typo or the voice was deleted | Re-copy the ID |
| Page shows the setup checklist | `ELEVENLABS_API_KEY` or every voice ID is missing | Fill `.env.local`, restart `pnpm dev` |

Every provider failure is logged server-side as `convert.provider_failed` with the provider's own `providerMessage`, which is usually self-explanatory.

## Environment variables

| Variable | Required | Description |
| --- | --- | --- |
| `ELEVENLABS_API_KEY` | yes | Dedicated, restricted ElevenLabs API key. Server-only; never prefixed with `NEXT_PUBLIC_`. |
| `ELEVENLABS_VOICE_WARM_ID` | at least one voice | Voice ID for *Warm Narrator* (`warm-narrator`). |
| `ELEVENLABS_VOICE_DEEP_ID` | at least one voice | Voice ID for *Deep Studio* (`deep-studio`). |
| `ELEVENLABS_VOICE_BRIGHT_ID` | at least one voice | Voice ID for *Bright Conversational* (`bright-conversational`). |
| `ELEVENLABS_MODEL_ID` | no | Defaults to `eleven_multilingual_sts_v2`. |
| `ELEVENLABS_REMOVE_BACKGROUND_NOISE` | no | `true` to enable ElevenLabs' noise isolation. Default `false`. |
| `ELEVENLABS_TIMEOUT_MS` | no | Provider timeout, 5 000–120 000. Default `45000`. |
| `MAX_AUDIO_DURATION_SECONDS` | no | Product limit, default `30`. Enforced client- and server-side. |
| `MAX_AUDIO_SIZE_MB` | no | Upload cap, default `15`. Set to `4` on Vercel (see Deployment). |

## Deployment (Vercel)

The demo above is a Git-connected Vercel project: every push to `main` builds and deploys production, and pull requests get preview deployments. To reproduce the setup:

1. Import the repository in Vercel and set the **Root Directory** to `voice-transformer` (the repository root has no `package.json`; without this setting Git builds fail). From the CLI: `vercel project update <project> --root-directory voice-transformer`.
2. Add the environment variables above under *Settings → Environment Variables* (Production and Preview as needed). Never commit `.env.local`.
3. Set `MAX_AUDIO_SIZE_MB=4`: Vercel serverless functions reject request bodies over 4.5 MB before the route runs. Uncompressed 30-second WAV files can exceed this; recordings made in the browser (WebM/Opus, a few hundred KB) are unaffected.
4. Push to `main` (or click Deploy). The `/api/convert` route runs on the Node.js runtime with `maxDuration = 60`. The page is rendered dynamically so configuration changes take effect on the next request after a redeploy.
5. Redeploy after changing environment variables (Deployments → ⋯ → Redeploy). When adding values with the CLI, pass the bare ID — inline `# comments` are fine in `.env.local` (Next strips them) but would be stored verbatim by `vercel env add`.

Any Node.js host that can run `next build && next start` works as well.

## Privacy

This application does not save recordings, generated audio, filenames, transcripts or any personal metadata. Source audio is held in memory only for the duration of the request; generated audio is streamed straight back to the browser and lives only as an in-memory Blob there until you discard it or leave the page.

Audio **is** sent to ElevenLabs for voice processing and is therefore subject to ElevenLabs' processing, retention and history policies for your account and plan. Zero-retention processing should not be assumed on the free plan. The UI says exactly this and no more.

For uploaded files the UI asks you to confirm you have permission to use the recording. Target voices are synthetic and developer-controlled; the app does not offer cloning or impersonation of real people.

## Free-plan economics

At the time of writing (September 2026):

- ElevenLabs Free: $0/month, roughly **10 000 credits/month**
- Voice Changer / Speech-to-Speech: roughly **1 000 credits per minute** of source audio
- That is about **10 minutes of conversion per month**, i.e. twenty 30-second requests or about eighty 5–8-second ones

Every request is capped at 30 seconds client- and server-side, files are rejected before contacting ElevenLabs whenever anything looks wrong, and quota exhaustion is shown as a clear "demo usage limit reached" message rather than a crash. Remaining credits are visible in the ElevenLabs dashboard under *Usage*, or via `pnpm check:elevenlabs` if the key has the `user_read` permission. Requests that fail with 4xx (wrong voice, bad plan) do not consume credits. Pricing and limits change; check the current [ElevenLabs pricing](https://elevenlabs.io/pricing) before relying on these figures.
